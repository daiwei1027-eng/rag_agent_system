# RAG Agent System — Day 18

This repository marks the transition from a notebook-driven Hugging Face playground to
an engineering-first Retrieval-Augmented Generation (RAG) project.

The Day 18 target is intentionally small:

```text
Question -> Retriever -> Top-k chunks -> Context -> Prompt -> LLM -> Answer + Sources
```

The project provides the package layout, configuration, shared types, logging, CLI entry
point, tests, and implementation contracts. The core RAG logic is deliberately left as
hands-on work.

## Setup

Python 3.10+ is required. From this repository root:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
```

Copy the Day 17 retrieval artifacts into `data/` yourself:

```text
data/tinystories.faiss
data/tinystories_chunks.json
```

The filenames can be changed in `configs/default.yaml`. These files are not generated by
this scaffold and are ignored by Git.

## Run

Current milestone (2026-09-30): retrieval works with 10,417 vectors and 384 dimensions.
The full RAG pipeline is still an exercise, not a completed application.

```powershell
python scripts/check_retrieval.py
```

The real-data smoke check returned the Lily/needle story as rank 1 (chunk 0,
score approximately 0.6050). This is one retrieval example, not a quality benchmark.
The current loader expects sequential IndexFlatIP labels and an explicit
`metadata.faiss_id` to `chunk_id` mapping. Counts and dimensions alone cannot
verify that text and vectors came from the same indexing run.

Existing tests report 2 passed and 2 intentionally skipped. They do not yet
cover the retriever's core behavior. See `docs/learning-log/2026-09-30.md`.

After completing the TODOs below:

```powershell
python scripts/run_rag.py --question "What is KV cache?"
```

or, after editable installation:

```powershell
rag-query --question "What is KV cache?"
```
