## 核心实现与设计理由

- `HistoryClient` 保持 `chat(messages, tools)` 返回契约；在调用模型之前将 messages/tools 深拷贝追加到 history。模型请求失败时也能保留输入，异常仍交给 Agent 原有逻辑处理。
- 每题开始清空 recorder.history；运行结束后复制到该题记录，避免跨题污染。计时只覆盖 Agent.run，不包含结束后的快照复制或写盘。
- TinyStories 模板和构造函数放入 `agents/prompts.py`。Agent 初始消息只有任务说明与问题，检索依据由工具 observation 回送；未在入口先检索并将答案证据塞进初始 prompt。
- 两组工具 handler 均召回配置的 20 条候选，再按合法请求的 top_k 选取；有重排组对候选排序，无重排组取原排序前若干条。工具尊重 top_k 参数，不静默改成 5；本次模型两组全部请求 5，实际均返回 5。不能把内部 RetrievedChunk 数据类直接作为 observation，需转换为稳定的六字段字典。
- 负例也进入 Agent 正式评估，用于检验拒答；它们只从没有相关 ID 分母的检索指标中排除，不从端到端任务中排除。

## 代表性失败与结论

- q001：两组都拿到 Lily 的证据；无重排组另加 Ben 的错误情节，有重排组核心答案正确，但仍缺引用。
- q022：无重排组正确回答鼓；有重排组把另一篇 Timmy 故事的小提琴混入答案，即使标注证据已排第一也会答错。
- q040：有重排组返回樱桃树证据并答对；无重排组未返回该证据，错误回答糖果故事。
- q042：有重排组返回目标故事的 some medicine，却把另一篇猫头鹰修理物品故事中的 laser 当成药名，属于跨故事关联；无重排组拒答，但没有目标故事支持。
- q045：两组都返回目标故事，却编造 50 克/10 克；有重排组还引用真实返回的 chunk 2500，该文段没有重量。引用 ID 存在不能证明它支持答案。
- q015：Agent 改写问题后，工具返回 5 条均未包含标注证据；答案又把年龄问题答成人名。本次未保存全部 20 候选，不能仅凭返回 5 条确定遗漏发生在候选召回还是重排。

本次重排增加了正例证据返回，但没有提高最终答案正确率；单次小样本也不能推出重排稳定降低拒答表现。生成侧存在跨故事混合、时态/事实越界、引用遗漏和无依据细节。严格通过低是这些缺陷叠加的结果，不等于整个 Agent 工具链路无法运行。

## 局限与下一步

12 题是固定且已经用于人工错误分析的小样本，45 题未拆训练/测试集，相关标注可能不完整。实际先运行有重排、后运行无重排，与原协议预设顺序不同，真实顺序保留，不能伪装成按原顺序执行。两次记录未保存模型权重 snapshot、完整依赖和硬件环境、Git 状态及显式 GPU 同步信息；基线可追溯，但不宣称跨机器逐位复现。上述 v1 评分收尾未重跑模型；同日随后由用户运行 v2，见下文。未执行全项目测试、未提交或推送 Git。

固定题集上的检索与 Agent 两组基线、人工评分和失败复盘已齐备。下一项优化选择“回答与依据的明确输出约束”：用户先设计并实现 v2 提示词，明确答案/依据格式、只引用直接支持的 chunk_id，缺少信息时表达“资料未说明”，保留人物关系和时态，不混合故事。暂不扩大候选、不换模型、不增加额外 Agent 框架。

对照选择已有有重排组，保持模型、候选数 20、题集、工具 schema 和评分规则不变，仅修改提示词并另存新目录。重点比较正例引用正确率、严格通过、答案正确和负例编造情况；必须核对实际模型检索 query/top_k 是否随提示变化，不能声称检索轨迹天然相同。优化结果只说明在已见题集上的效果，不外推为独立测试表现。

面试表达：我将检索命中与端到端质量分开评估。重排使工具返回标注证据从 5/9 增至 6/9，但人工核对后两组答案正确均为 4/9，说明拿到证据仍不足以保证模型正确使用。请求快照让我能够定位跨故事混合、虚假引用和错误拒答，下一步以单一提示词改动做同口径对照，而不是只报告 completed 或检索命中率。

### 耗时局限与下一步

两次 v2 的 q002 只预热了模型生成，没有实际触发检索和重排推理。组件权重虽已加载，检索/重排的首次实际推理仍可能包含初始化开销。更短中位耗时主要伴随从两轮带工具调用退化为一轮直接文本；不能宣称优化使完整 Agent 链路更快，或将其视为与 v1 相同口径的完整预热收益。

本次实验没有达到整体质量改善目标，应作为失败实验保留。一个待验证的原因假设是：新增输出/拒答示例与工具行动规则混在初始消息中，使模型在没有 observation 时直接进入回答或拒答阶段。请求快照只能证明实际行为，不能单凭结果断定具体哪条规则或提示长度是原因。

下一步先明确阶段顺序：“先获取工具文段 → 再判断证据是否足够 → 最后按格式回答”，把“尚未调用工具”和“工具结果不足”区分开；保留工具自主选择，不在评估入口提前检索替模型作决定。先诊断工具触发，暂不扩候选、不换模型、不追加更长规则或框架。新版本仍保存独立目录并沿用原评分；任何调试小样本不得替代正式固定 12 题结果。
