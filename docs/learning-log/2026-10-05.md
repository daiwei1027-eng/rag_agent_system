# RAG Agent System — Day20 Retrieval Evaluation

日期：2026-10-05

## 完成目标

基于 TinyStories 建立并复核 40 条 query-ground truth 标注，实现批量检索评估，对同一批 FAISS Top20 候选比较原排序与 Cross-Encoder 重排后的排序。

本次仅评估检索证据，不调用生成模型。Day19 的单问题实验扩展为可按问题追踪、可汇总指标的评估流程。

## 评估集与标注规则

- 语料为 `data/tinystories_chunks.json`，共 10,417 个 chunk。
- 标注文件为 `data/evaluation/tinystories_queries_draft.jsonl`，共 40 条英文问题。文件名仍保留 `draft`，用户已完成复核并在失败分析后修正部分内容。
- 每条记录包含 `query_id`、`query` 和 `relevant_chunk_ids`；相关 ID 来自真实语料。
- 一个相关 chunk 应能独立提供问题答案。相同人物名字或相似主题不等于相同故事的证据。
- 多个相关 ID 表示多个能独立回答问题的 chunk，不表示必须将这些 chunk 拼接才能回答。
- 问题由阅读语料后设计，覆盖事实、原因、同义改写与多个条件，主要衡量已知可回答问题的证据检索能力。

最终记录使用修正后的问题集：q005 补充相关 ID `1001`，q038 修改问题以明确猫直接向另一只动物求助的情节。该修正版可称为评估集 v2；此名称是本记录的版本说明，当前脚本尚未保存独立的版本字段。

## 实验流程与参数

```text
读取 JSONL 标注
    ↓
每个问题召回一次 FAISS Top20
    ├─ 原顺序 → Baseline 指标
    └─ Cross-Encoder 对同一批候选重排，保留 Top20 → Reranker 指标
    ↓
保存逐问题排序与指标 → 对每个指标求问题平均值 → 保存 CSV 和配置
```

| 参数 | 实际值 |
|---|---|
| 问题数量 | 40 |
| Embedding 模型 | `sentence-transformers/all-MiniLM-L6-v2` |
| 查询向量归一化 | `true` |
| FAISS 候选数量 | 20 |
| Reranker | `cross-encoder/ms-marco-MiniLM-L6-v2` |
| 评估时重排保留数量 | 20 |
| Reranker 最大输入长度 | 512 tokens |
| Reranker batch size | 8 |
| Recall 截断位置 | 1 / 3 / 5 |
| Hit Rate 截断位置 | 5 |
| MRR 截断位置 | 20 |

重排保留 Top20 是为了让两组 MRR@20 使用同样的候选范围，不使用日常回答流程中的 Top5 截断。重排排名根据返回列表位置计算，原有 `RetrievedChunk.rank` 仍表示 FAISS 排名。

当前 `config.json` 仍包含生成温度、生成模型与上下文等字段。这些是项目配置值，本次没有使用，不能作为检索实验的影响因素。

## 指标定义

- Recall@k：前 k 条命中的不同相关 ID 数 / 标注相关 ID 总数，再对问题取平均。
- HitRate@5：每条问题的 Top5 至少包含一个相关 ID 时记为 1，否则为 0，再取平均。
- RR@20：前 20 条中第一个相关结果位置的倒数；未命中记为 0。
- MRR@20：所有问题 RR@20 的平均值。

重复 ID 不能重复增加 Recall；先截取前 k 条，再去重。空检索结果记为 0，空标注报错，k 必须是正整数且不能是布尔值。

## 最终结果

以下结果来自修正后的 40 条问题集，使用 `per_query.json` 逐条重算后与 `total.csv` 一致。

| 指标 | Baseline | + Reranker | 绝对变化 |
|---|---:|---:|---:|
| Recall@1 | 0.4250 | 0.8375 | +0.4125 |
| Recall@3 | 0.6000 | 0.9375 | +0.3375 |
| Recall@5 | 0.6625 | 0.9375 | +0.2750 |
| HitRate@5 | 0.6750 | 0.9500 | +0.2750 |
| MRR@20 | 0.5844 | 0.9250 | +0.3406 |

Baseline 在 27/40 条问题的 Top5 中命中至少一个标注证据；重排后为 38/40。Recall@5 提升 27.50 个百分点。MRR@20 的变化按未四舍五入的结果计算约为 0.3406。

验证确认：40 个 query_id 唯一；每条两组均含 20 个不同候选 ID，候选集合一致；保存的逐问题指标符合公式，汇总值与 CSV 一致。

## 失败分析与标注修正

### q005：漏标导致正确结果被判为失败

问题：Lucy 帮妈妈打扫房子后得到了什么？答案是一个白色小屋。

原标注只有 `1000`。检查发现 `1001` 也明确描述 Lucy 打扫房子后妈妈给她白色小屋。该 chunk 在 Baseline 中排第 9，重排后排第 1，因此补充为 `relevant_chunk_ids = ["1000", "1001"]`，重新计算两组指标。

修正后重排 HitRate@5 为 1、Recall@5 为 0.5、RR@20 为 1。两个标注 chunk 只召回一个，因此 Recall 与 Hit Rate 不相等。不能把证据副本召回率直接当作问题是否已有答案证据。

### q007：相似故事干扰，目标证据未进入 Top20

问题：Max 离开滑梯后，谁一起滑下来并拥抱？答案为 Ben 和 Lily，证据位于 `1500`。

两组候选均不包含 `1500`。两组第一名都是 `4443`，内容是 Lily 和 Max 等待一个大男孩让出滑梯，没有目标问题中的 Ben 与拥抱情节。

这说明候选集合包含相似人物和场景，却未召回指定情节。当前可确认是标注目标的候选召回失败，尚不能证明具体由 Embedding 模型还是分块方式造成。

### q038：明确问题后，目标证据仍未召回

修正后的问题：Who examined the bird's wing and gave it medicine after the cat took it directly to another animal for help?

答案为猫头鹰，证据位于 `9250`。原问题容易与另一篇猫叫来主人、主人将鸟送往兽医的故事混淆，因此补充“直接向另一只动物求助”的条件，并重新运行检索。

修正后 `9250` 仍未进入 Top20。重排第一名 `5552` 是 Lily 与妈妈带鸟看兽医的故事；第二名 `8634` 是猫通过主人帮助鸟看兽医的故事。它们与受伤小鸟的治疗主题相近，但不满足修正后问题的情节。

剩余两条问题 q007、q038 的目标证据均未进入候选池，Reranker 无法将不存在的候选补回。

## 结论与局限

在这份 40 条 TinyStories 标注集上，Cross-Encoder 在固定 Top20 候选内明显改善了证据排序。此次没有评估生成答案准确率、答案引用、延迟或显存，不能据此宣称端到端回答质量或生产性能已经改善。

标注质量直接影响指标：q005 的漏标曾将实际命中误判为失败。相关性复核不能只依靠检索排名，仍需回看原始语料并检查相邻 chunk。

评估集规模较小，且问题由语料设计；没有独立保留的测试集。本次指标用于学习验证与当前实验比较，不代表真实用户问题分布或更广泛的泛化能力。
