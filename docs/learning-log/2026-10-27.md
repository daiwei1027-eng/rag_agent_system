# 2026-10-27：CLI 与 Agent factory 检索模式接线收尾

## 范围与实现

用户在 cli.py 和 agents/factory.py 的检索器构造处增加
`mode=config.retrieval.mode`，让 YAML 中已校验的模式进入实际业务组件。
此前两处未传 mode，实际会使用构造器默认的 dense；检索评测脚本此前已传 mode，
因此既有 Dense/BM25/Hybrid 实验不受这两处缺参影响。

两处保留 FaissRetriever 名称；它是 DocumentRetriever 的别名，可以分派三种模式。
沿用现有 Agent factory，不增加新的 Retriever factory 或接口层。
助手未改生产实现，只准备配置夹具和机械性验收。

## 已确认的数量语义与限制

CLI：先按 retrieval.top_k 检索，启用重排时使用 reranker.top_k，
最后按 context.top_k 截取生成上下文。

Agent 工具：不重排时按工具参数 top_k 检索；开启重排时先按 retrieval.top_k
取得候选，再重排返回工具请求的 top_k。这里的数量策略与离线评测候选预算不是自动等同的。

本轮完成模式接线收尾，不代表 SEC 问答业务已迁移完成。
