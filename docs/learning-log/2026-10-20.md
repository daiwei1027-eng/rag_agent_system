## 本地 manifest 校验

实现位于 [sec_manifest.py](../../src/rag_agent_system/ingestion/sec_manifest.py)。
用户完成核心实现，助手经明确授权补充根对象与每条文档的必要字段检查。

校验职责包括：清单结构、版本、必要字段、字段类型与非空约束，重复 ID 与解析后
重复路径，HTML 文件存在性，raw 目录边界，实际字节数和 SHA256 一致性。
允许草稿中的来源字段尚为空；本地一致性校验与来源认证分开。

学习要点：

- Path.resolve() 解析绝对路径、.. 和符号链接；默认不证明文件存在。
- source_file 相对于 manifest 所在目录解析；raw_dir 是允许范围，不再次拼入文件路径。
- 使用路径层级判断目录归属，不能用字符串前缀代替。
- 对原始二进制字节计算 SHA256，用 hexdigest() 获得 64 个十六进制字符。
- 先检查类型再调用 len()；整数校验排除 bool；缺字段应主动给出可定位的错误。

## HTML 结构与函数职责

BeautifulSoup 将 HTML 转成保留父子关系的树。find() 向下找后代，find_parent()
沿祖先链向上找最近匹配；调用对象决定查找起点。urlsplit(href).fragment 提取 #
后面的锚点标识，但不保证该目标存在。

Microsoft 标题可能拆在多个 span 中，不能盲目在标签文字间加空格。
例如 BUSINESS 可能拆成 B 和 USINESS。正文文字归一化与用于识别页眉的文字比较
是不同用途，不能默认所有位置都采用同一种 get_text 分隔方式。

| 函数 | 职责 | 返回 |
| --- | --- | --- |
| find_section_anchor | 精确匹配统一空白后的目录标题，提取并验证唯一目标 | 锚点 ID |
| collect_section_elements | 按文档顺序收集开始之后、结束之前的标签 | list[Tag] |
| select_content_blocks | 选择互不嵌套的文字候选块与最外层表格 | list[Tag] |
| is_noise_block | 根据当前文档结构判断空块、页脚和目录页眉 | bool，True 表示删除 |

目录同名链接指向同一目标时集合去重；指向多个不同目标则报歧义。每份报告分别
解析并定位 anchors，不跨文档复用。三个章节边界为 Business → Risk Factors、
Risk Factors → Unresolved Staff Comments、MD&A → Market Risk，均排除结束锚点。

六份文件的结构检查表明：Microsoft 使用带语义 ID 的 p 标题和
main-content-container；NVIDIA、Alphabet 使用带生成 ID 的空 div 锚点，没有该
正文容器。因此不能将 Microsoft 的 p 遍历和容器过滤直接套到其他公司。

候选块选择先排除 table 内部子元素，整体保留最外层 table；其余仅选择没有更深
p/div/table/ul/ol/li 的 p/div/li。这样避免父容器、段落、span 重复贡献文字。
排版过滤目前针对已观察结构：MSFT 删除正文容器外块；NVDA/GOOG 检查祖先的
position:absolute 与 bottom:0；目录页眉同时检查完整文字和对应目录链接。
纯数字不等于页码，正文年份和表格数据不能按数字形式直接删除。
