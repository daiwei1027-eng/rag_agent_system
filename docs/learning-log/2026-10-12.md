# RAG Agent System — 阶段一收尾：真实 Agent 链路与运行记录

日期：2026-10-12

## 范围与产出

在已有手写 Agent Loop 上，用本地 Qwen 跑通直接回答、calculator、time、真实 FAISS 检索与 CrossEncoder 重排、同轮多工具和工具失败回传。`scripts/run_agent.py` 现在支持 `--scenario`、`--all` 和可选的 `--record-dir`，可将代表性运行保存为 UTF-8 JSON；Git 提交和推送由用户完成。

最终记录位于 `data/agent_runs/stage1-2026-10-12/`，共 7 份：原定的 6 类场景，以及额外的 `tinystories_auto`，专门检查模型能否在未指定工具名时自行检索。每份记录包含运行时间、完整配置、Agent 运行参数、工具 schema、每轮模型收到的消息和工具定义，以及 `status / answer / trace / error`。`trace` 保留 assistant 工具请求、工具 observation 与最终回答。模型请求快照只存在于保存的运行文件中，`AgentResult` 仍保持原来的四字段契约。

复现命令（在项目根目录和 `hf_llm` 环境中）：

```powershell
python scripts/run_agent.py --all --record-dir data/agent_runs/stage1-2026-10-12
```

本次批量运行在本地设置 `HF_HUB_OFFLINE=1` 和 `TRANSFORMERS_OFFLINE=1`，以使用已经下载的模型文件，避免受网络检查影响。记录目录由命令参数决定；单场景也可用 `--scenario` 指定。

## 真实运行结果

| 场景 | 关键证据 | 结果 |
|---|---|---|
| `direct` | trace 只有 user → assistant；没有工具 observation | 直接回答水的化学式为 H2O |
| `tinystories` | search_documents 返回 3 条重排文段，`chunk_id=0` 排第一 | 回答 `Lily`，并输出 `依据：chunk_id=0` |
| `tinystories_auto` | 问题未指定工具名；模型自主调用 search_documents，返回 `chunk_id=0` | 回答 `Lily`，但最终文字漏写 chunk_id |
| `calculator` | calculator 的 `ok=true, result=96` | 最终回答 96 |
| `time` | time 使用 `timezone_name=Asia/Shanghai`，结果带 `+08:00` | 最终回答使用工具时间 |
| `multi_tool` | 同一轮请求 time 和 calculator；两条 observation 均 `ok=true` | 最终回答同时使用时间和 96 |
| `tool_failure` | calculator 对除数 0 返回 `ok=false`、`ValueError` | 最终明确说明无法计算，没有编造数值 |

七次任务级 `status` 均为 `completed`。`tool_failure` 的工具级 `ok=false` 与任务级 `completed` 不矛盾：模型收到失败 observation 后给出了明确解释。保存文件已重新读取核对：七份 JSON 均可解析，模型请求中的消息快照与 trace 前缀一致，工具 observation 和上述结果对应。

## 设计与排错

- 检索工具先从 FAISS 召回配置数量的候选，再由 CrossEncoder 重排并返回模型请求的 `top_k` 条。每条结果固定包含 `chunk_id`、`text`、向量 `score`、`source`、`rerank_score` 和 `rerank_rank`；未重排时后两项为 `null`，避免返回结构随配置变化。
- 初次在未指定工具名的 TinyStories 问题上，模型直接声称无法访问资料库。将工具描述写清楚为“可检索本地 TinyStories”后，它开始自行选择检索；另一版英文提示曾使模型连续生成过多工具调用并在 token 上限处截断，适配器按残缺标签返回 `model_error`。最终使用“如需检索，只提出一次简短英文查询”的问题，得到一次成功检索和正确答案。这说明工具选择与调用数量仍受提示和模型能力影响。
- Windows 控制台曾在打印含特殊字符的文段时发生编码异常。脚本现先写 JSON 再打印，并对无法编码的控制台字符使用转义替代；UTF-8 文件保存原始字符。
- 记录文件保留模型接口输入（messages 和 tools）及规范化响应，未保存 tokenizer 渲染后的完整 prompt、模型原始 token 序列、索引文件哈希或各轮耗时。绝对路径也与当前机器有关，尚不能称为跨机器的逐位复现。

## 验证范围与后续

相关单元检查：`tests/test_schemas.py`、`tests/test_search_documents.py`、`tests/test_tool_registry.py`、`tests/test_reranker.py`，**43 passed**。最终批量真实运行退出代码为 0，并生成七份记录；这不是全项目测试或稳定成功率评估。

阶段一的实际模型、工具、检索和失败回传链路已形成可审查样例。自主检索案例的证据编号未出现在最终文字中，应作为后续回答质量评估的一项失败记录，而不因 `status=completed` 被忽略。下一阶段先建立可重复的 RAG/Agent 评估与延迟基线，再根据错误样例优化检索、重排和答案引用；后端服务化建立在稳定的调用契约和这些基线之上。

面试表达：我将本地 Qwen 的工具调用格式适配到手写 Agent 协议，统一任务级返回结构，并用真实 FAISS、CrossEncoder、calculator 和 time 验证单工具、多工具及失败回传。运行记录同时保存模型输入、工具请求、observation 和最终回答；单次成功只证明链路可运行，工具选择与来源引用的稳定性仍需通过成组评估测量。
