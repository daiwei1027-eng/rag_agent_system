# RAG Agent System — Day22 Tool Calling

日期：2026-10-06

## 完成目标

手写 calculator、search_documents、time 三类工具的 schema，完成通用参数校验、工具注册表、执行入口和结构化 observation。用户亲手完成核心实现并逐步编写测试；本记录整理当天验证结果与排错经验。

本次先使用手写请求模拟模型生成的 tool call，搜索使用假检索器。没有调用 LLM，也没有实现将 observation 返回模型后的 Agent 循环。

## 核心原理

```text
LLM 生成工具名称和参数（本次用手写请求模拟）
    ↓
程序校验 tool call 格式
    ↓
registry 按工具名查找 schema 和 handler
    ↓
按 schema 校验 arguments
    ↓
handler(**arguments) 执行 Python 函数
    ↓
返回 observation
    ↓
后续阶段：应用程序将 observation 放回模型输入
```

schema 描述工具能力与参数约束，本身不会执行函数。模型提出调用请求，应用程序决定是否执行并提供结果。

## 工具契约与实现

| 工具名 | 参数约束 | 返回值 |
|---|---|---|
| `calculator` | `operation` 为四种运算之一；`a`、`b` 为数字，排除布尔值 | 运算结果；除零时抛出 `ValueError` |
| `search_documents` | `query` 为字符串，最小长度 1；`top_k` 为 1–10 的整数，排除布尔值 | 文档字典列表，没有命中返回 `[]` |
| `time` | `timezone` 为 `UTC` 或 `Asia/Shanghai` | 带偏移的 ISO 8601 当前时间字符串 |

三个 schema 均要求上述参数必填，并设置 `additionalProperties: False`。
搜索字典包含 `chunk_id`、`text`、`source`、`score`，其中 score 转为 Python float。

时间适配函数将 schema 的 `timezone` 映射到 `get_current_time(timezone_name=...)`。
搜索适配函数通过闭包绑定程序提供的 retriever，模型只传 query 和 top_k。
registry 不需要为具体工具添加分支。

| 文件 | 职责 |
|---|---|
| `src/rag_agent_system/tools/schemas.py` | 三类工具的名称、描述与参数规则 |
| `src/rag_agent_system/tools/validation.py` | 通用参数校验，合法时返回 None，非法时抛异常 |
| `src/rag_agent_system/tools/registry.py` | 注册、导出 schemas、请求校验、执行和失败结果包装 |
| `src/rag_agent_system/tools/calculator_tool.py` | 四则运算 |
| `src/rag_agent_system/tools/time_tool.py` | 当前时间查询 |
| `src/rag_agent_system/tools/search_docments.py` | 包装现有 retrieve 接口；沿用实际文件名 |
| `scripts/tool_calling_demo.py` | 独立演示入口 |

注册表保存 `工具名称 → {schema, handler}`，拒绝重复名称和不可调用的 handler。
`callable(handler)` 只检查对象可否调用，注册阶段不执行函数，也不验证参数签名。

`execute()` 检查外层字典、必填字段、arguments 字典类型、id/name 字符串类型及非空白值，再查找工具、校验参数并执行一次。
`execute_safe()` 捕获 TypeError 和 ValueError，返回失败 observation；其他异常仍向外抛出。
非字典请求或缺失字段的请求也能生成失败 observation，无法取得的 ID/名称返回 None。

## Observation 格式

成功结果：

```json
{
  "tool_call_id": "call_003",
  "name": "calculator",
  "ok": true,
  "result": 96
}
```

失败结果：

```json
{
  "tool_call_id": "call_004",
  "name": "calculator",
  "ok": false,
  "error": {
    "type": "ValueError",
    "message": "Please provide a nonzero b"
  }
}
```

observation 外层是字典；搜索工具的 result 是字典列表。调用 ID 用于将结果对应回原请求。

异常断言结合错误信息，避免测试因为另一条规则报错而假通过。

Demo 复核结果：

| 调用 | 实际结果 |
|---|---|
| 搜索 RAG，top_k=3 | 返回一条预设文档 `chunk_001`，score=0.85 |
| 查询 UTC 时间 | 返回带 `+00:00` 的当前时间；值随运行变化 |
| 12 × 8 | 返回 96 |
| 12 ÷ 0 | 返回 ok=false、ValueError 和 nonzero 错误信息，程序继续运行 |

假检索器不会自动产生 top_k 条文档；top_k 表示请求数量，结果可以少于该数量。
这次演示验证了执行流程，没有衡量真实检索质量、模型工具选择能力或端到端回答效果。
JSON 输出用于观察结果，当前没有持久化执行日志。

## 当天排错与学习要点

1. 区分实际参数与规则：arguments 是用户数据，properties 位于 parameters_schema 中。
2. JSON Schema 用 string/integer/number 描述类型，不能写 question 或 int；多一层花括号可能创建集合，而不是嵌套字典。
3. 必填校验用字段成员判断，不能用真假值判断；a=0 和 arguments={} 都可能合法。
4. 未声明 enum 时跳过检查，不能把默认空列表当作允许值；范围比较必须允许上下限相等。
5. validate_arguments 合法时返回 None，不能放在 if 条件中控制执行，应先校验、再执行。
6. 包内模块导入使用完整包路径，避免将 validation 误当成顶层模块。
7. 工具名称以 schema 的 name 为准，time_tool/get_current_time 是文件或函数名，不是注册名称。
8. execute 的失败测试用 pytest.raises；execute_safe 的失败测试断言返回 observation。
9. 字段检查应先确认请求类型，再检查字段存在，最后检查字段类型和值，避免 KeyError。
10. 安全执行包装只调用一次 execute，避免工具副作用重复发生。

## 当前局限与后续任务

- 校验器只实现本次规则子集，尚未校验 schema 自身。当前 enum 仅在字符串分支检查，不能宣称支持任意类型枚举。
- 当前长度和范围检查位于类型检查之前。后续应前置类型检查，补 query=123、top_k="3" 等测试，保证错误来源和信息清楚。
- minLength=1 允许纯空白查询，后续需要在查询业务边界拒绝空白值。
- 时间工具用固定 UTC+8 表示上海当前时间，没有支持历史时区转换或其他地区。
- 数字未检查 NaN/Infinity，也未限制输出大小、超时或执行权限；execute_safe 不是隔离执行机制。
- 请求与 observation 是内部协议，尚未适配具体模型 API。下一阶段接入真实模型的 tool call，将 observation 返回模型，并限制调用轮数。
- 搜索工具尚未在本 Demo 中验证真实 FAISS 检索；后续绑定真实 retriever 时需单独记录数据、模型和配置。
