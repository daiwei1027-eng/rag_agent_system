# RAG Agent System — Day19 Reranker

本项目实现了两阶段检索：先用 Embedding Retriever 召回 Top20，再通过 Cross-Encoder Reranker 重排，选取 Top5 作为 LLM 的回答上下文。

Day19 完成重排实现和单问题 before/after 实验；Day20 使用问题集和指标验证效果。

## 流程

```text
问题 → Embedding Retriever → 同一批 Top20
                               ├─ 原排序取 Top5 → LLM
                               └─ Reranker → Top5 → LLM
```

对照实验固定问题、候选文档、上下文数量、提示词和生成模型，仅改变是否重排。

## Retriever 与 Reranker 的区别

| 对比 | Embedding Retriever | Cross-Encoder Reranker |
|---|---|---|
| 输入 | 分别编码问题和文档 | 联合输入问题与文档文本 |
| 评分 | 向量相似度 | 模型预测相关性分数 |
| 文档预计算 | 可以提前计算向量、建立索引 | 针对具体问题重新评分 |
| 用途 | 从知识库快速召回候选 | 对少量候选细致排序 |

建立索引和查询时应使用一致的 Embedding 模型。Reranker 不需要与 Embedding 模型一致，但必须使用与自身匹配的 tokenizer。

重排分数用于排序，不一定是概率，也不能直接与向量检索分数比较。正确证据未进入 Top20 时，Reranker 无法将其补回。

## 当前配置

| 环节 | 设置 |
|---|---|
| Embedding | `sentence-transformers/all-MiniLM-L6-v2` |
| 向量检索 | FAISS，Top20 |
| Reranker | `cross-encoder/ms-marco-MiniLM-L6-v2` |
| 重排保留数量 | Top5 |
| 最大重排输入长度 | 512 tokens |
| 重排批大小 | 8 |
| LLM | `Qwen/Qwen2.5-1.5B-Instruct` |
| 最大生成长度 | 256 tokens |
| 实验生成温度 | 0 |

日常配置位于 `configs/default.yaml`。对照脚本将生成温度覆盖为 0，并在实验 JSON 中记录实际值。

`retrieval.top_k` 控制召回数量，`reranker.top_k` 控制重排保留数量，`context.top_k` 控制实际交给 LLM 的数量。

## 主要文件

| 文件 | 职责 |
|---|---|
| `src/rag_agent_system/config.py` | 读取 YAML、校验参数和数量关系 |
| `src/rag_agent_system/models.py` | 定义文档、检索结果和回答的数据结构 |
| `src/rag_agent_system/retrieval/faiss_retriever.py` | 向量检索 |
| `src/rag_agent_system/retrieval/reranker.py` | 延迟加载 Cross-Encoder、评分、排序和截取 |
| `src/rag_agent_system/pipeline.py` | 协调检索、可选重排、上下文和生成 |
| `src/rag_agent_system/cli.py` | 根据配置创建组件，提供命令行
